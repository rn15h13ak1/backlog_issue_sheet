# backlog_issue_sheet

Excel に書いた内容で Backlog の課題を **作成・更新** する CLI ツールです。Backlog の課題を同じ書式の Excel に **書き出す** こともできます。

- Excel の **列が Backlog の項目** に対応し、1 行が 1 課題になる。値は ID ではなく名前（担当者名・種別名など）で書く
- **「登録」シートで作成、「更新」シートで変更**。1 つのブックで両方を扱える
- **親子関係** を指定できる。登録シートでは行の並びで、更新シートでは課題キーで指定する
- **カスタム属性** は、その名前を見出しにした列を足すだけで使える
- 既定は **ドライラン**。何を作り、どの項目がどう変わるかを確かめてから反映できる
- 書き出した Excel を編集して取り込みに戻すと、**変えたセルだけ** が更新される

似たツールに `../excel_to_backlog` があります。あちらは、台帳の 1 行を Markdown の本文に整形して登録するものです。こちらは、Excel を入力フォームとして使い、Backlog の各項目をそのまま書きます。

## インストール

Python 3.10 以上が必要です。仮想環境に入れます。

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e .
```

`backlog-issue-sheet` コマンドが使えるようになります。

```bash
backlog-issue-sheet --help
```

## 設定

**1. 設定ファイルを作る**

```bash
cp config.example.yaml config.yaml
```

`config.yaml` に、スペースのホスト名とプロジェクトキーを書きます。1 回の実行で扱うプロジェクトは 1 つです。

```yaml
backlog:
  space_host: "yourcompany.backlog.com"
  project_key: "MYPROJ"
```

**2. API キーを置く**

API キーは設定ファイルには書きません（[共通規約 C](../ws-conventions/README.md#設定ファイル)）。環境変数か、設定ファイルと同じ場所の `.env` に書きます。`.env` は追跡しません。

```bash
echo 'BACKLOG_API_KEY=YOUR_API_KEY_HERE' > .env
```

探す順番は、環境変数 `BACKLOG_API_KEY` → 設定ファイルと同じ場所の `.env` → 作業ディレクトリの `.env` です。

設定ファイルは、作業ディレクトリの `config.yaml`、ツールの場所の `config.yaml` の順に探します。`--config` で指定することもできます。

## 使い方

| コマンド | 内容 |
|---|---|
| `backlog-issue-sheet template` | プロジェクトに合わせたひな形の Excel を作る。カスタム属性も列として並び、種別・担当者などにはプルダウンが付く |
| `backlog-issue-sheet import 課題.xlsx` | 検証して、作成・変更の予定を表示する（ドライラン）。何も送らない |
| `backlog-issue-sheet import 課題.xlsx --execute` | 確認のうえで Backlog に反映する |
| `backlog-issue-sheet export` | Backlog の課題を Excel に書き出す |
| `backlog-issue-sheet master` | Excel に書ける名前（種別・担当者・カテゴリー・カスタム属性と選択肢など）を一覧する |

対話メニューもあります。オプションを覚えなくても、番号を選ぶだけで実行できます。Windows では `menu.bat` をダブルクリックしても起動できます。

```bash
python menu.py
```

### 同梱のひな形

Backlog に接続しなくても、[`templates/課題シート.xlsx`](templates/課題シート.xlsx) をコピーして使い始められます。

| シート | 内容 |
|---|---|
| 使い方 | 書き方の要点 |
| 登録 / 更新 | 空の入力シート。ここに書いた内容を取り込む |
| 記入例（登録） / 記入例（更新） | 書き方の例と、各行の意味（`#説明` 列）。取り込みでは読まれない |

列は標準の項目だけです。カスタム属性は、その名前を見出しにした列を足して使います。プルダウンには Backlog の既定の値（優先度・状態・完了理由・種別の初期値）が入っています。担当者・カテゴリー・カスタム属性の選択肢まで入ったひな形が欲しいときは、`backlog-issue-sheet template` で作ってください。

### はじめて使うときの流れ

```bash
cp templates/課題シート.xlsx 課題.xlsx        # 同梱のひな形を使う
# または backlog-issue-sheet template -o 課題.xlsx（プロジェクトに合わせたひな形）
# 課題.xlsx を編集する
backlog-issue-sheet import 課題.xlsx           # 予定を確かめる
backlog-issue-sheet import 課題.xlsx --execute --limit 2   # まず 2 件だけ反映して確かめる
backlog-issue-sheet import 課題.xlsx --execute
```

`--limit` で一部だけ反映した後に全件を実行すると、反映済みの行がもう一度作られます。続きは、出力された結果のファイル（[出力されるファイル](#出力されるファイル)）を見て、未反映の行だけを残してから実行してください。

`import` の主なオプション:

| オプション | 内容 |
|---|---|
| `--execute` | 実際に送信する。付けなければドライラン |
| `--yes` | 確認を省く。対話できない環境（タスクスケジューラなど）で実行するときに必要 |
| `--limit N` | 送信が発生する行のうち、先頭から N 件だけ送る |
| `--debug` | 送信内容を表示する。API キーは表示しない |

## Excel の書式

1 行目が見出しで、2 行目から 1 行が 1 課題です。**列は見出しの名前で読み取ります。** 並び順は問わず、使わない列は消して構いません。

### 「登録」シート：課題を新しく作る

| 親課題キー | 子課題 | 件名 | 詳細 | 種別 | 優先度 | 担当者 | 期限日 | … |
|---|---|---|---|---|---|---|---|---|
| | | 親タスクA | | タスク | 中 | 山田太郎 | 2026-10-31 | |
| | ○ | 子タスクA-1 | | タスク | 中 | | | |
| PROJ-50 | | 既存課題の下に付ける子 | | タスク | 中 | | | |

- 件名・種別・優先度は必須です
- 課題キーの列は置けません（既存の課題を変えるときは「更新」シートを使います）
- 状態と完了理由も書けます。Backlog は作成時にこれらを受け付けないため、作成した直後に更新で反映します（API を 2 回呼びます。ドライランにもそう表示します）

### 「更新」シート：既存の課題を変更する

| 課題キー | 親課題キー | 件名 | 状態 | 担当者 | 期限日 | … |
|---|---|---|---|---|---|---|
| PROJ-101 | PROJ-50 | | | | | |
| PROJ-102 | (解除) | | | | | |
| PROJ-103 | | | 処理中 | (削除) | 2026-10-31 | |

- 課題キーは必須です
- **空のセルは変更しません。** 値を消すときは `(削除)` と書きます
- 件名・種別・優先度・状態は消せません（`(削除)` と書くとエラーになります）
- 今と同じ値を書いた項目は、変更として扱いません

### 「プロジェクト」シート：どのプロジェクト向けのブックか

| プロジェクトキー | MYPROJ |
|---|---|

A 列に `プロジェクトキー`、その右のセルにキーを書きます。取り込むとき、設定ファイルの `project_key` と照らし合わせ、**違えばエラーにして何も送りません。** 大文字と小文字の違いは問いません。

課題キーを 1 つも書かない「登録」シートは、設定が別のプロジェクトを指していても気づく手がかりがありません。種別や優先度の名前は既定のままのプロジェクトが多く、別のプロジェクトでもそのまま通ってしまうためです。

- `backlog-issue-sheet template` で作ったひな形、書き出したファイル、実行結果のファイルには、はじめから入っています
- 同梱のひな形（`templates/課題シート.xlsx`）は特定のプロジェクト向けではないため、空になっています。使うときに書いてください
- シートが無いブックや、値が空のブックも取り込めます。その場合は、確かめられなかったことを「注意」として表示します

### 値の書き方

| 項目 | 書き方 |
|---|---|
| 件名・詳細 | そのまま。詳細はセル内で改行できる |
| 種別・優先度・状態・完了理由・担当者 | 名前で書く。担当者はログイン ID でもよい（同姓同名がいるときはログイン ID で書く） |
| カテゴリー・発生バージョン・マイルストーン | 名前。複数あるときは改行（Alt+Enter）か「,」「、」で区切る |
| 開始日・期限日 | 日付のセル、または `2026-10-31` / `2026/10/31` |
| 予定時間・実績時間 | 数値 |

名前が Backlog に無いときは、似た名前を「もしかして」として示します。使える名前は `backlog-issue-sheet master` で確かめられます。

見出しが `#` で始まる列は読み飛ばします。自分用のメモに使えます（例: `#備考`）。「登録」「更新」以外のシートも読みません。

## 親子関係

Backlog の親子は **1 階層まで** です。子課題を親にしたり、子を持つ課題を子にしたりはできません。違反は送信前に検出してエラーにします。

### 登録シート

| 書き方 | 意味 |
|---|---|
| `子課題` に `○` | 上へさかのぼって、**最初に見つかった「子課題ではない行」** の子になる |
| `親課題キー` に課題キー | 既にある、その課題の子になる |
| どちらも空 | 親のない課題になる |

`○` のほか、`〇` `1` `yes` なども受け付けます。`×` など読めない値はエラーにします（「子ではない」の意味で書いたものを、子として扱わないため）。

親課題キーを書いた行も子課題なので、`○` の行の親にはなりません。さらに上の行が親になります（その旨を注意として表示します）。上に親になれる行が無い `○` の行はエラーです。

**行の順番が親子関係を表すので、並べ替えないでください。** ドライランの表示で、親子がどう決まったかを確かめられます。

```
■ 登録シート（作成 4 件）
  2行目   親タスクA
  3行目     └ 子タスクA-1（親: 2行目）
  4行目     └ 子タスクA-2（親: 2行目）
  5行目     └ 既存課題の下に付ける子（親: PROJ-50）
```

### 更新シート

| 親課題キーの値 | 動作 |
|---|---|
| 課題キー | その課題の子にする（付け替えも含む） |
| `(解除)` | 子課題ではない課題にする |
| 空 | 親子関係を変えない |

制約は、**シート全体を反映した後の状態** で判定します。たとえば「A を親から外し、B を A の子にする」は、両方が同じシートにあれば通ります。送信するときは、親から外す行を先に、親を付ける行を後に送ります。

## カスタム属性

**標準の項目以外の見出しは、カスタム属性の名前として扱います。** 設定ファイルへの記述は要りません。見出しは Backlog のカスタム属性名と完全に一致させます。

| 型 | 書き方 |
|---|---|
| 文字列・文章 | そのまま |
| 数値 | 数値 |
| 日付 | 日付のセル、または `2026-10-31` |
| 単一リスト・ラジオ | 選択肢の名前 |
| 複数リスト・チェックボックス | 選択肢の名前を改行か「,」で区切る |

- Backlog に無い名前の見出しはエラーにします（打ち間違いで値が送られないまま進むのを防ぐため）
- 種別ごとの必須の属性が空のとき、その種別で使えない属性に値があるときも、送信前にエラーにします

## 取り込みの流れ

1. **検証** ― 両シートの全行を読み、見出し・必須項目・名前・日付や数値・親子の制約を確かめます。**エラーが 1 件でもあれば、何も送りません。** エラーは「シート・行・列・理由」の形で全件表示します
2. **予定の表示** ― 登録シートは親子をツリーで、更新シートは変わる項目を「旧 → 新」で表示します
3. **確認** ― `--execute` のとき、1 回だけ確認します
4. **送信** ― 登録シート（上から）→ 更新シート（親から外す行 → 親を付ける行）の順に送ります

1 件の失敗では止めず、残りを続けます。ただし、認証・権限のエラーが出たら以降は送りません。親の作成に失敗した行の子は作りません（作っても親子にならないため）。

## 書き出し

```bash
backlog-issue-sheet export                       # 完了以外のすべて
backlog-issue-sheet export --include-closed      # 完了も含める
backlog-issue-sheet export --status 未対応 処理中
backlog-issue-sheet export --type バグ --keyword ログイン
backlog-issue-sheet export --parent PROJ-1       # この課題とその子課題
backlog-issue-sheet export --key PROJ-1 PROJ-5
```

- **「更新」シートの書式** で出力します。カスタム属性はすべて列になります
- 親の直後にその子が並びます。子だけが条件に当たった場合は、親も加えます
- 参照用に `#URL` と `#更新日時` の列を付けます。見出しが `#` で始まるので、取り込みでは無視されます
- コメント・添付ファイル・共有ファイル・通知先は扱いません
- 詳細が Excel のセルの上限（32,767 文字）を超える課題は、詳細を空にして書き出し、その旨を表示します。空のセルは「変更しない」なので、取り込みに戻しても本文は消えません

**書き出したファイルをそのまま取り込みに戻しても、差分は出ません。** 一部のセルだけを直して戻せば、その項目だけが更新されます。

## 出力されるファイル

`output/`（設定の `output_dir`、または `--output-dir`）に出力します。**元の Excel は変更しません。**

| ファイル | 内容 |
|---|---|
| `課題シート_日時.xlsx` | `template` のひな形（`-o` で変えられる） |
| `書き出し_日時.xlsx` | `export` の結果（`-o` で変えられる） |
| `run_日時.csv` | 実行ログ。1 件送るたびに書くので、途中で止まってもどこまで反映したか分かる |
| `結果_日時.xlsx` | 作成・更新した課題を「更新」シートの書式で並べたもの。課題キー入り。続けて修正するときはこのファイルを使える |

日時は秒までです。同じ秒に続けて実行して同じ名前のファイルが既にあるときは、`_2`、`_3` … を付けて、前のファイルを上書きしません。1 回の取り込みで出す `run_` と `結果_` は、同じ番号にそろえます。`-o` で名前を指定したときは、指定どおりの名前で保存します（既にあれば上書きします）。

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 成功（ドライラン、確認で中止した場合を含む） |
| 1 | 検証エラーがあった／送信に失敗した行・未実行の行があった／API エラー |
| 2 | 設定・引数・ファイルの誤り |
| 130 | Ctrl+C で中断した |

## 制約と注意

- **値を消す・親から外す操作は、実際の Backlog ではまだ確かめていません。** `(削除)` は空の値（複数値の項目は `categoryId[]=` の形）で、`(解除)` は `parentIssueId` を空で送ります。最初は `--limit 1` で 1 件だけ反映し、Backlog の画面で結果を確かめてください
- 数式のセルは、最後に Excel で保存したときの計算結果を読みます。Excel 以外で作ったファイルは計算結果を持たないことがあります
- 読めるのは `.xlsx` / `.xlsm` です。`.xls` は Excel で `.xlsx` に保存し直してください
- 通知先・コメント・添付ファイルは扱いません

## 開発

```bash
pip install -e ".[dev]"
python -m pytest -q -p no:warnings
```

同梱のひな形は生成物です。生成元（`sheet_io.py` の書式や `scripts/make_default_template.py` の記入例）を変えたら作り直します。何度作っても同じバイト列になるようにしてあり、作り直し忘れはテストが検出します。

```bash
python scripts/make_default_template.py
```

テストは偽の Backlog（`tests/conftest.py` の `FakeBacklog`）を使い、実際の API には接続しません。偽物も Backlog と同じく親子の制約を守り、順番を誤った更新は拒否します。

`backlog_client.py` は `../excel_to_backlog/backlog_client.py` をコピーしたものです。由来と、取り込むときの注意はファイルの冒頭にあります。

共通の規約は [`../ws-conventions/README.md`](../ws-conventions/README.md) に従います。リポジトリ固有の取り決めは [`CLAUDE.md`](CLAUDE.md) にあります。
